## 캡처 순서 (PPT 슬라이드별)

### 슬라이드 1 — 표지 (① 가맹점 정보 기재)
직접 텍스트로 작성:
- (1) 상호명: 토스페이먼츠
- (2) 사업자번호: 123-45-678
- (3) URL: https://...
- (4) Test ID / (5) Test PW

### 슬라이드 2 — 하단 정보 (② Footer 캡처)
**캡처 대상 페이지**: 사이트 메인(/) 또는 쇼핑몰(/shop) 또는 결제 가능한 임의 페이지
**캡처 영역**: 페이지 하단의 footer 부분 (상호/대표자/사업자번호/통신판매업신고/주소/전화 모두 보이게)
**확인 사항**:
- 6개 필수 항목 모두 표시 (`SiteFooter` 컴포넌트 적용된 페이지)
- 도메인 주소·시간 함께 보이게

### 슬라이드 3 — 환불규정 (③)
**캡처 대상 페이지**: `/refund-policy`
**캡처 영역**: 무형상품 환불 조항 — 제2조(구독), 제3조(자몽), 제4조(기관 월결제) 또는 제5조(쇼핑몰)
**확인 사항**: 결제일 후 N일 이내 환불 가능 등 명시 부분 표시

### 슬라이드 4 — 로그인/회원가입 (④)
**캡처 대상 페이지**: `/login`, `/signup`
**확인 사항**:
- 아이디/비밀번호 입력 필드
- 로그인 후 다음 단계로 이동하는 흐름 (1~2장)
- 비회원 구매 안 됨 → 로그인 필수임을 보여주는 화면

### 슬라이드 5 — 상품 선택·구매 과정 (⑤)
국어농장은 4가지 결제 흐름이 있으므로 **각각의 흐름마다 1세트씩** 캡처. 무형상품 위주.

#### 5-A. 구독 결제 흐름
1. `/start` (학습 메뉴 그리드 → 프로 모드 클릭 → "구독 필요" 모달 또는 `/subscription`)
2. `/subscription` — 1/3/6/12개월 옵션 카드
3. 옵션 선택 후 결제 페이지 (상품명, 금액 표시)
4. "결제하기" 또는 "구독 시작" 버튼

#### 5-B. 자몽 충전 흐름 (개인)
1. `/start` → "내 자몽 지갑" 카드
2. `/my/grapefruit` — 잔액 + 충전 프리셋 (1만/3만/5만/10만원)
3. 충전 옵션 선택 → 결제 페이지
4. "결제하기" 버튼

#### 5-C. 자몽 충전 흐름 (기관 관리자)
1. 관리자 로그인 → `/admin/grapefruit-wallet`
2. 충전 프리셋 선택
3. 결제 페이지

#### 5-D. 기관 월 사용료 흐름
1. 관리자 → `/admin/billing`
2. 미결제 청구서 표시 + "결제" 버튼

#### 5-E. 쇼핑몰 흐름 (유형상품)
1. `/shop` — 상품 목록
2. 상품 클릭 → `/shop/products/:productId` — 상세
3. 장바구니 추가 또는 즉시 구매
4. 주문서 페이지 (상품명, 수량, 금액, 주문자/배송 정보, 결제수단)
5. "결제하기" 버튼

> ⚠️ 각 흐름마다 **상품/서비스의 명칭, 이미지, 상세설명, 금액**이 결제페이지·결제창까지 일관되게 보여야 합니다.

### 슬라이드 6 — 카드 결제 경로 (⑥)
**캡처 대상**: 토스 결제창 (테스트 모드)
1. "결제하기" 클릭 직후 토스 결제창 모달
2. 카드 선택 (신용/체크카드 + 카드사 아이콘들)
3. **약관 전체 동의** 화면 (전자금융거래 기본약관 / 개인정보 수집 및 이용 동의 / 개인정보 제3자 제공 안내) — **반드시 캡처**
4. "다음" 버튼

비씨 카드의 경우 (별도):
- 페이북 화면 (간편 결제 / 기타 결제 선택)
- 비밀번호 결제 또는 페이북 앱 결제 화면

빌링(정기결제) 카드 등록의 경우:
- 카드 정보 입력창 (카드번호 / 유효기간)
- 본인 정보 입력창 (이름 / 주민번호 앞 7자리 / 통신사 / 휴대폰번호 / 인증번호)

## 토스 가맹 신청 절차 요약

1. 위 가이드대로 PPT 6단계 구조로 결제경로 파일 작성
2. 토스페이먼츠 가맹 신청 폼에 다음 함께 제출:
   - 결제경로 PPT (.pptx)
   - 사업자등록증 사본
   - 통신판매업신고증 사본
   - 대표자 신분증 사본
   - 정산 계좌 통장 사본
3. 카드사 심사 통과 후 라이브 client key 발급
4. `frontend/.env` 또는 `application.yml` 의 `TOSS_CLIENT_KEY` 를 라이브 키로 교체
5. PaymentService 의 mock 결제 분기 제거 (Phase D 통합 작업)
