1기능의 목적

한 학생/한 반에 대해 시험 범위(행) × 학습 자원(열)의 매트릭스로 할일을 박아 두고, 학생이 수행한 결과를 자동·수동으로 셀에 누적·검수하는 통합 학습 관리 도구.
  • 시험 대비·정규 학습 진도·자유 글쓰기·테스트 응시 등 이질적인 학습 단위 4종(국어농장 콘텐츠 · 학습활동 파일 제출 · 테스트 · 글쓰기)을 한 평면에 묶음.
  • 어드민(본사·기관)에게는 권한 범위 내 모든 학생의 진행 현황·제출·미수행을 한 화면에서 보고, 셀 단위로 검수·점수·메모를 박을 수 있는 컨트롤 패널 역할.
  • 학생·학부모에게는 "오늘 뭐 해야 하나"를 모달·캘린더·매트릭스로 안내하는 To-Do 보드.

5실제 프로세스 (역할별)

본사 · 기관 관리자

  1. 기관 default 템플릿 설계 (선택) — 학습 계획표 1개를 만들어 is_template=true 표식 → 이후 가입 학생에게 자동 복제. 기존 학생은 POST /v1/admin/study-plans/{id}/apply-to-students 로 일괄 반영.
  2. 학생별 탭 진입 → 상단 학생 셀렉터(기관·반·학생 3단) → 학생의 활성 plan 1건(list[0]) 매트릭스 로드.
  3. 행 추가(예: "2학기 중간 1주차")·열 추가(국어농장 1·테스트 1·글쓰기 1 …) → "동일 추가" 알약으로 같은 반에 propagate.
  4. 셀 클릭으로 콘텐츠/시험/주제 검색·마감일·라벨 배정 → 학생에게 노출.
  5. 캘린더 탭에서 일자별 액션 집계 확인 → 학생별 드릴다운 → 셀 모달에서 검수/점수/메모.
  6. 제출물 탭(activity 전용)·테스트 탭·글쓰기 탭에서 자산 종류별 일별 진행 모아보기 → 행 클릭 시 학생별 탭/외부 결과 화면으로 점프.

학생

  1. 로그인 후 홈에서 StudyPlanReminderModal 로 미수행/임박 활동 안내.
  2. /study-plan 진입 → plan select(여러 개 가능) → "할일 목록"(매트릭스) 또는 "캘린더".
  3. 셀 클릭 → 자산별 화면 점프 (학습 콘텐츠 / OMR 응시 / 글농장 글쓰기 / 사진 제출 페이지). unassigned 셀은 무반응.
  4. 제출/응시 시 셀 상태가 submitted/scored/completed 등으로 전이, 캘린더 진행률 게이지에 반영.

A. 정합성 · 로직 오류 ★★★ 시급

A-1 "학생당 plan 1개 가정" — 학생이 plan 2개 이상이면 데이터 누락 ★★★
StudentMatrixTab.jsx:46 의 const target = plans[0] 한 줄로 첫 plan 만 편집 대상으로 잡습니다. 그런데 학생이 plan 2개를 갖게 되는 경로가 실제로 존재합니다:
  • (a) createDefaultPlanForStudent 가 만든 default plan + (b) 어드민이 새 plan 을 만들어 그 학생을 target 으로 박는 경우 → 어드민 화면은 (a)만 편집, 학생 화면(StudyPlanPage)은 select 로 (a)·(b) 둘 다 노출 → 어드민이 박은 행/열이 학생 화면에서 안 보일 수 있음.
  • 학생 화면도 첫 plan(plans[0]) 만 캘린더 진행률 게이지에 반영 — 다른 plan 의 임박 활동은 안 보임.

StudyPlanCreateForm.jsx:64-66 이 빈 배열을 강제 → 어드민이 새 plan 을 만들면 cell 0개 상태. 자동 생성된 default plan 과 별도로 또 빈 plan 이 생기는 구조라 A-1 문제를 유발합니다. 신규 plan 의 의도도 모호.

8.1 propagateDelta — "다른 학생에게 배정이 안 박힘" 의 root cause

핵심 결함

StudyPlanService.kt:1836 propagateDelta() 의 동작 범위가 "scope/asset 라벨 복제 + 빈 cell 자동 생성"까지로 끝납니다. 셀 내부의 실제 배정 데이터(콘텐츠·마감일·복수배정 리스트)는 전혀 복제되지 않습니다.

✅ 복제되는 것
  • scope 라벨 (행 이름)
  • asset 라벨 · assetType · assetKind
  • asset.refId (열 단위 기본 콘텐츠)
  • 빈 cell 생성 (status=unassigned)
❌ 복제 안 되는 것
  • cell.cellRefId — 셀의 개별 배정 콘텐츠 ID
  • study_plan_cell_assignments — 국어농장 셀의 복수 콘텐츠 (N개 묶음)
  • cell.dueAt — 마감일
  • cell.assignedLabel · cell.score

코드 증거

  • propagateDelta 본문(1900-1990) 에서 cellAssignmentRepo 호출 0건. 복제 루프는 createCell(plan.id, scope.id, asset, uid) 만 호출 (라인 1931 · 1972).
  • createCell() (1504-1516) 은 항상 cellRefId = if (asset.assetType == "korfarm" && asset.refId != null) asset.refId else null 로만 채움 — 즉 asset 의 기본 refId 만 옮기고, 소스 셀의 cellRefId/assignments 는 무시.
  • 결과: 받는 학생 plan 에 행/열은 생성되지만 셀은 모두 "배정 전" 상태로 출발 → UI 상 "배정이 안 됨" 으로 보이는 정확한 원인.

패치 방향 — propagateDelta 셀 데이터까지 복제 확장

P-1A 소스 셀 데이터를 함께 복제하는 옵션 추가

새 행/열이 생성될 때, 같은 source plan 의 동일 scope/asset 위치의 셀 데이터를 함께 옮긴다.

// propagateDelta 의 sourceScopes.forEach 안에서
val sourcePlanCells = cellRepo.findByPlanId(sourcePlanId)
val sourceCellMap = sourcePlanCells.associateBy { "${it.scopeId}_${it.assetId}" }
val sourceAssignmentsMap = cellAssignmentRepo.findByCellIdIn(sourcePlanCells.map { it.id })
                                              .groupBy { it.cellId }

// 새 scope/asset 한 쌍으로 만들어지는 cell 마다:
val srcCell = sourceCellMap["${s.id}_${a.id}"] ?: return@inner
val newCell = createCell(plan.id, newScopeId, newAsset, uid)
newCell.cellRefId      = srcCell.cellRefId
newCell.dueAt          = srcCell.dueAt           // 학생마다 +N일 보정 옵션
newCell.assignedLabel  = srcCell.assignedLabel
newCell.status         = if (srcCell.cellRefId != null) "pending" else "unassigned"
cellRepo.save(newCell)

// 국어농장 복수 배정 복제
sourceAssignmentsMap[srcCell.id]?.forEach { a ->
    cellAssignmentRepo.save(StudyPlanCellAssignmentEntity(
        id = IdGenerator.newId("spca"),
        cellId = newCell.id, refId = a.refId,
        assignedLabel = a.assignedLabel,
        status = "pending",
        dueAt = a.dueAt, sortOrder = a.sortOrder
    ))
}
  • 새 request 필드 includeCellData: Boolean = true (default true) 로 켜고 끄기.
  • 마감일은 학생별 가입일·기존 plan 의 startDate 등을 고려해 보정 옵션 (dueOffsetMode: "as-is" | "shift-from-today") 제공.
  • 국어농장 외 자산(test/writing/activity) 도 cellRefId/dueAt 까지 복제.

P-1B 라벨 충돌 시 셀 데이터 처리 정책

대상 학생 plan 에 같은 라벨의 scope/asset 이 이미 있을 때 셀 데이터 복제 정책.

  • skip — 기존 라벨 유지, 셀 데이터도 안 건드림 (현재 동작 그대로).
  • overwrite — 라벨·sortOrder 만 덮어쓰던 현행을 셀의 cellRefId·dueAt·assignments 도 덮어쓰도록 확장.
  • 새 옵션 merge — 행/열은 유지, 셀 데이터만 덮어씀 (라벨 보존 + 콘텐츠 재배정).

8.2 셀/행/열 단위 일괄 복제 기능 신설

현재 UI는 "행/열 추가 직후 알약" 으로만 propagate 모달 진입. 이미 만들어진 셀을 어드민이 매트릭스에서 골라 다른 학생에게 박는 진입점이 백엔드·프론트 모두 부재합니다.

P-2A 셀 단위 복제 API 신설

새 endpoint: POST /v1/admin/study-plans/cells/{cellId}/propagate

{
  "targetScope": "org" | "class" | "users",
  "classId":     string?,    // class 일 때
  "userIds":     string[]?,  // users 일 때
  "conflictPolicy": null | "skip" | "overwrite" | "merge",
  "dueOffsetMode":  "as-is" | "shift-from-today",  // default "as-is"
