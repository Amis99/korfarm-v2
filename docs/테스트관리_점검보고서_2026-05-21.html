1점검 목적·범위

학습 계획표 점검(N-1~N-11) 작업이 마무리된 시점에서, 테스트(시험) 관리 기능을 4 페르소나 입장에서 시뮬레이션해 결함·UX 사고를 발굴.

  • 범위: 기타(misc) 시험만 — 진단·챕터는 별도 엔진
  • 임시 계정 정책: SQL 직접 삽입 + u_sim_* / org_sim prefix → 점검 후 자동 cleanup (완료)
  • 검증: API 라이브 호출 + 코드 정독 (file:line 인용)
  • 산출물: 본 HTML 보고서 + N-12~N-17 후속 작업 항목
학습 계획표 점검 보고서(8.13)와 동일 양식. 발견된 사고는 본 보고서에 기록만 — 패치는 별도 작업 N-12~N-17 로 등록.

8.2 현재 동작 분석 (왜 계속 같은 사고가 났는가)

① 진단 + 챕터 테스트 — EngineShell + ExamModule (moduleKey="exam")

EngineShell.jsx:544-561:

useEffect(() => {
  if (status !== "RUNNING") return;
  if (timeLeft > 0) return;
  setSeed((prev) => {
    const nextSeed = Math.max(0, prev - 1);
    if (nextSeed === 0) {
      if (preventAutoFinish) {
        setSeedExhausted(true);
        setStatus("PAUSED");
        return 0;
      }
      finish(false, { seed: 0 });  // ← 시험 모드에서도 자동 finish 호출
      return 0;
    }
    setTimeLeft(timeLimit);  // ← 학습 모드 패턴: 씨앗 차감 후 timer 재시작
    return nextSeed;
  });
}, [timeLeft, status, timeLimit, preventAutoFinish]);

이 useEffect 는 학습 모드의 "씨앗 차감" 로직인데 시험 모드(isExam) 에서도 그대로 동작한다. 결과: timeLeft 가 0 도달하면 시험에서도 finish(false, ...) → 학생 답안 강제 제출 → 결과 페이지 자동 이동. 학생이 보기엔 "갑자기 화면이 사라짐 / OMR 마킹 못 함". 이것이 김유건 학생 사고의 직접 원인.

이전 N-20A 작업은 "새로고침 시 잔여시간 복원" 만 해결, "timer 만료 후 동작" 은 그대로 학습 모드 로직 사용.
