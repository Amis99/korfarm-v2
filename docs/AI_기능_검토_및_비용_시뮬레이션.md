# 국어농장 AI 기능 검토 및 비용 시뮬레이션

> 작성일: 2026-04-12
> 목적: 4개 AI 기능의 구현 가능성 및 월간 유지 비용 분석

---

## 1. 기능 개요

| # | 기능 | 대상 | 핵심 동작 |
|---|---|---|---|
| 1 | **학생 AI 어시스턴트** | 학생 | 로그인 시 학습 상태 분석, 강약점 요약, 추천 학습 + 페이지 링크 제시, 고민 상담 |
| 2 | **관리자 AI 어시스턴트** | 기관 관리자 | 로그인 시 기관 현황 브리핑, 자연어 명령으로 스케줄/과제/학생관리 직접 실행 |
| 3 | **AI 글쓰기 첨삭** | 학생 (글쓰기) | 원고지에 쓴 글을 AI가 자동 첨삭 (어노테이션 + 코멘트), 관리자 확인 후 확정 |
| 4 | **커뮤니티 AI 참여** | 전체 | 커뮤니티 채팅에 AI가 참여, 대화 맥락 기반 질문 답변 |

## 2. 구현 가능성 평가

### 기능 1: 학생 AI 어시스턴트

| 필요 데이터 | 현재 상태 | 비고 |
|---|---|---|
| 학습 이력 (점수/정답률/씨앗) | `/v1/learning/farm/history` | FarmHistoryEntry 전체 필드 |
| 10대 역량 분석 | `DiagnosticReport.competencyDetails` | 역량별 점수/등급/내러티브/백분위 |
| 강점/약점 | `strongCompetencies`, `weakCompetencies` | 상위 3개/하위 3개 + 오류경로 |
| 시험 성적 | `TestReportResponse` | 영역별/문항별 상세 |
| 일일 학습 현황 | `DailySeedStatusResponse` | 오늘 진행 현황 |
| 구독 상태 | `SubscriptionView` | 유/무료 구분 |
| 페이지 링크 | 학생 라우트 40+개 | 동적 파라미터 포함 |
| 채팅 UI | WebSocket 커뮤니티 채팅 존재 | 컴포넌트 재활용 가능 |

**판정: 구현 가능 (난이도 중)**. 기존 데이터 풍부, 읽기 전용이라 리스크 낮음.

### 기능 2: 관리자 AI 어시스턴트

| 필요 데이터 | 현재 상태 | 비고 |
|---|---|---|
| 학생 관리 CRUD | 완비 | 목록/생성/수정/비활성화/구독변경 |
| 수강반 관리 CRUD | 완비 | 반 생성, 학생 추가/제거 |
| 학습 계획표 | 완비 | 범위-에셋 매트릭스, 셀 관리, 스케줄 |
| 과제 시스템 | 완비 | 과제 생성/마감/재개/제출현황 |
| 통합 성적표 | 완비 | `UnifiedReportResponse` 전체 구조 |
| 콘텐츠 관리 | 완비 | CRUD + 문제 일괄 교체 |
| 자연어 → API 실행 | **미구현** | LLM function calling 레이어 필요 |

**판정: 구현 가능 (난이도 상)**. 데이터/API는 충분하나, 자연어 → API 실행 변환과 실행 확인 UX 추가 필요. 오동작 리스크 존재.

### 기능 3: AI 글쓰기 첨삭

| 필요 요소 | 현재 상태 | 비고 |
|---|---|---|
| 학생 글 저장 | `WisdomPostEntity` | 원고지 텍스트 또는 파일 업로드 |
| 관리자 첨삭 구조 | `WisdomFeedbackEntity` | comment + correction(JSON 어노테이션) |
| 어노테이션 형식 | `[{id, page, startIdx, endIdx, comment}]` | 원고지 셀 인덱스 기반 |
| AI 채점 선례 | `EssayGradingService` + `AiGradingClient` | Claude API 연동 이미 구현됨 |
| 관리자 UI | AdminWisdomDetailPage | "AI첨삭" 버튼 있으나 비활성 상태 |

**판정: 구현 가능 (난이도 중하)**. AI 채점 시스템(`AiGradingClient`)이 이미 존재하고, 어노테이션 JSON 형식도 확정됨. 가장 빠르게 구현 가능한 기능.

### 기능 4: 커뮤니티 AI 참여

| 필요 요소 | 현재 상태 | 비고 |
|---|---|---|
| 채팅 메시지 저장 | `ChatMessageEntity` | roomId, userId, content, messageType |
| 메시지 히스토리 API | `GET /v1/chat/rooms/{roomId}/messages` | before 기반 페이징, 50개 단위 |
| WebSocket 브로드캐스트 | `ChatWebSocketHandler` | message.new 이벤트로 전파 |
| 채팅방 구조 | roomId = "community" (현재 1개) | 확장 가능 |
| 메시지 타입 | text, notice, image, voice, file, emoticon | AI는 text 타입 사용 |

**판정: 구현 가능 (난이도 중)**. AI 전용 시스템 사용자 생성 + 트리거 로직(멘션/질문 감지) 필요. 대화 맥락 길어지면 토큰 비용 증가에 주의.

```
사용자 ──브라우저──▶ 프론트엔드 (React)
                       │
                  ┌────┴────┐
                  │ AI Chat │ (SSE 스트리밍)
                  │  Panel  │
                  └────┬────┘
                       │ POST /v1/ai/chat
                       ▼
              ┌─────────────────────┐
              │  AiChatService (신규) │
              │                     │
              │  1. 역할별 시스템 프롬프트 │
              │  2. 컨텍스트 수집       │
              │  3. LLM API 호출      │
              │  4. function calling  │
              │  5. SSE 응답 스트리밍   │
              └──────────┬──────────┘
                         │
         ┌───────┬───────┼───────┬───────┐
         ▼       ▼       ▼       ▼       ▼
     학습이력   진단    관리자   글쓰기   채팅
     API      API     API     API     API
```

### 기능별 데이터 흐름

| 기능 | 입력 | LLM 처리 | 출력 |
|---|---|---|---|
| 1. 학생 AI | 학습이력+진단+역량+시험 | 분석 + 추천 생성 | 텍스트 + 페이지 링크 |
| 2. 관리자 AI | 기관현황+학생목록+스케줄 | 분석 + function calling | 텍스트 + API 실행 + 링크 |
| 3. AI 첨삭 | 원고지 텍스트 + 첨삭 기준 | 오류 탐지 + 코멘트 생성 | 어노테이션 JSON + 총평 |
| 4. 커뮤니티 AI | 최근 대화 히스토리 + 질문 | 맥락 파악 + 답변 | 텍스트 메시지 |

## 7. 비용 구조 분석

### 7.1 비용 비중

4개 기능 전체 구현 시, 비용의 **85% 이상이 기능 1(학생 AI)**에서 발생한다.

| 기능 | 비중 | 이유 |
|---|---|---|
| F1 학생 AI | ~85% | 학생 수 × 매일 1회 = 대량 세션 |
| F4 커뮤니티 AI | ~7% | 메시지 중 15%에만 응답하지만 누적량 |
| F2 관리자 AI | ~7% | 관리자 수 자체가 적음 |
| F3 AI 첨삭 | ~1% | 에세이는 월 몇십 편 수준 |

### 7.2 비용 절감 전략

| 전략 | 절감 효과 | 적용 대상 |
|---|---|---|
| **프롬프트 캐싱** | 입력 비용 20~40% 절감 | 전 기능 (시스템 프롬프트 반복) |
| **모델 티어링** | 50~70% 절감 | F1/F4는 저가 모델, F2/F3는 고급 모델 |

### 기능별 난이도 순위
