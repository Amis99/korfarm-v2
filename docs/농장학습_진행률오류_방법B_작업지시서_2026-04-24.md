# 농장 학습 진행률 오류 작업 지시서

작성일: 2026-04-24  
작성 목적: 다른 AI가 안전하게 이어받아 수정할 수 있도록, 현재 확인된 문제와 사용자가 결정한 작업 방향을 한 문서에 모은다.

## 사용자가 결정한 원칙

- 배포하지 않는다.
- 현재 워크트리가 다른 AI 작업과 섞여 있으므로 광범위한 git 작업을 하지 않는다.
- `git add .`, `git reset`, `git checkout --`, `git clean` 같은 명령은 사용하지 않는다.
- 코드 수정은 이 문서를 읽는 다음 작업자가 맡는다.
- 해결 방향은 **방법 B**로 확정한다.
- 방법 B란, 백엔드에 옛날 `/page-progress` API를 되살리지 않고 프론트에서 그 호출을 제거하는 방식이다.

## 문제를 아주 쉽게 설명하면

농장 학습 화면이 서버에 이런 질문을 한다.

> "이 학생이 이 콘텐츠를 몇 페이지까지 했고, 페이지별 정확도는 몇 퍼센트야?"

그런데 서버에는 그 질문을 받는 주소가 없다.  
그래서 사용자가 농장 학습 목록에서 진행률 창을 열면, 화면이 진행 정보를 못 불러오는 상태가 된다.

## 확인된 실제 문제

프론트 파일:

- `frontend/src/pages/FarmListPage.jsx`

현재 이 파일은 두 종류의 진행률 요청을 한다.

1. 정상으로 보이는 요청
   - 위치: `frontend/src/pages/FarmListPage.jsx:155`
   - 호출: `/v1/learning/farm/progress`
   - 용도: 목록에 있는 여러 콘텐츠의 학습수, 완료수, 내 상태를 가져온다.

2. 문제가 되는 요청
   - 위치: `frontend/src/pages/FarmListPage.jsx:168`
   - 호출: `/v1/learning/farm/page-progress`
   - 용도: 진행률 모달에서 페이지별 완료 현황을 가져오려고 한다.
   - 문제: 백엔드에 해당 API가 없다.

백엔드 파일:

- `backend/src/main/kotlin/com/korfarm/api/learning/FarmLearningController.kt`

현재 백엔드의 농장 학습 API는 아래만 있다.

- `GET /v1/learning/farm/history`
- `GET /v1/learning/farm/daily-seed-status`
- `POST /v1/learning/farm/start`
- `POST /v1/learning/farm/complete`
- `POST /v1/learning/farm/progress`

즉 `/v1/learning/farm/page-progress`는 없다.

DB 단서:

- `backend/src/main/resources/db/migration/V0040__content_page_progress.sql`
  - 예전에 `content_page_progress` 테이블을 만들었던 흔적이 있다.
- `backend/src/main/resources/db/migration/V0046__study_content_module.sql:90`
  - 나중에 `DROP TABLE IF EXISTS content_page_progress;`로 삭제했다.

판단:

- 예전에는 페이지별 진행률 기능이 있었거나 계획되어 있었다.
- 이후 학습 구조가 바뀌면서 DB와 백엔드 기능은 제거됐다.
- 프론트 일부 코드만 예전 방식으로 남아 사라진 API를 계속 부르고 있다.

## 방법 B로 해야 하는 이유

사용자는 방법 B를 선택했다.

방법 B는 다음 뜻이다.

- 백엔드 API를 새로 만들지 않는다.
- 삭제된 DB 테이블을 되살리지 않는다.
- 프론트에서 없는 API 호출을 제거한다.
- 현재 살아 있는 `/v1/learning/farm/progress` 결과만 사용한다.

이 방법이 안전한 이유:

- DB 구조를 건드리지 않아도 된다.
- 운영 DB 마이그레이션 위험을 늘리지 않는다.
- 백엔드 배포 없이 프론트 오류만 줄일 수 있다.
- 현재 워크트리가 복잡한 상황에서 수정 범위가 가장 작다.

## 다음 AI가 수정해야 하는 범위

권장 수정 파일은 원칙적으로 하나다.

- `frontend/src/pages/FarmListPage.jsx`

가능하면 백엔드 파일, DB 마이그레이션, 배포 스크립트는 건드리지 않는다.

수정 방향:

1. `pageProgress`, `pageProgressLoading`, `pageProgressError` 상태를 제거하거나 더 이상 API 의존 상태로 쓰지 않는다.
2. `progressModal`이 열릴 때 `/v1/learning/farm/page-progress`를 호출하는 `useEffect`를 제거한다.
3. 진행률 모달은 이미 받아온 `progress?.myStatus?.[contentId]`와 `progress?.stats?.[contentId]`만 사용한다.
4. 페이지별 진행률 UI는 제거하거나 단순 문구로 바꾼다.
5. "이어서 학습" 버튼은 페이지 계산 없이 `/learning/{contentId}`로 이동시킨다.
6. "처음부터" 버튼도 필요하면 유지하되, `startPage=1` 의존이 실제 러너와 맞는지 확인한다. 확신이 없으면 단순히 `/learning/{contentId}`로 통일한다.

권장 UX 문구:

- 상태가 `NONE`이면: `아직 학습 전입니다.`
- 상태가 `STARTED`이면: `진행 중인 학습입니다.`
- 상태가 `COMPLETED`이면: `완료한 학습입니다.`
- 전체 통계는 가능하면 표시:
  - `전체 학습수 {startCount}`
  - `완료 {completeCount}`

중요:

- 페이지별 정확도, 페이지별 씨앗, 마지막 완료 페이지 같은 문구는 제거한다.
- 이유는 현재 백엔드가 그 데이터를 제공하지 않기 때문이다.

## 건드리지 말아야 할 것

- `/v1/learning/farm/page-progress` 백엔드 API를 새로 만들지 않는다.
- `content_page_progress` 테이블을 다시 만들지 않는다.
- DB 마이그레이션을 추가하지 않는다.
- AWS 배포를 하지 않는다.
- 현재 다른 AI가 작업한 파일을 되돌리지 않는다.
- 광범위 포맷팅을 하지 않는다.
- 관련 없는 ESLint 오류를 한꺼번에 고치지 않는다.

## 예상 수정 후 화면 흐름

수정 전:

1. 농장 목록 진입
2. 특정 콘텐츠 클릭
3. 진행률 모달 열림
4. `/page-progress` 요청 실패
5. `진행 정보를 불러오지 못했습니다.` 표시

수정 후:

1. 농장 목록 진입
2. 특정 콘텐츠 클릭
3. 진행률 모달 열림
4. 이미 목록에서 불러온 `/progress` 데이터로 상태 표시
5. 사용자는 `학습 시작` 또는 `학습 계속` 버튼으로 학습 화면 이동

## 검증 방법

수정 후 최소 검증:

1. `npm.cmd run build`
   - 프론트 빌드가 통과해야 한다.
2. 농장 화면에서 콘텐츠 클릭
   - 진행률 모달이 열려야 한다.
   - `진행 정보를 불러오지 못했습니다.`가 뜨지 않아야 한다.
3. 브라우저 개발자 도구 Network 확인
   - `/v1/learning/farm/page-progress` 요청이 더 이상 없어야 한다.
   - `/v1/learning/farm/progress` 요청은 유지되어도 된다.
4. 학습 이동 버튼 확인
   - 클릭 시 `/learning/{contentId}`로 이동해야 한다.

선택 검증:

- `npm.cmd run lint`
  - 현재 프로젝트 전체 린트는 이미 실패 상태다.
  - 이 작업 때문에 새 오류가 늘어나지 않았는지만 확인하면 된다.

## 완료 기준

이 작업은 아래 조건을 만족하면 완료로 본다.

- `FarmListPage.jsx`에서 `/v1/learning/farm/page-progress` 문자열이 사라진다.
- 농장 진행률 모달이 없는 API에 의존하지 않는다.
- 백엔드와 DB는 건드리지 않는다.
- 프론트 빌드가 통과한다.
- 배포는 하지 않는다.
- 작업 파일만 명확히 기록한다.

## 사용자에게 설명할 때의 짧은 버전

농장 화면이 사라진 옛날 서버 기능을 부르고 있어서 오류가 났습니다.  
서버와 DB를 다시 키우는 방식은 위험하니 하지 않고, 화면에서 그 옛날 기능 호출을 빼는 방향으로 결정했습니다.  
앞으로는 이미 살아 있는 전체 진행 상태만 보여주고, 페이지별 진행률 표시는 제거합니다.
