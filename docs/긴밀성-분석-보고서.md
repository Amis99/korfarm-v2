## 2. 공통 인프라 긴밀성 — 양호 (A)

### 2-1. 인증 체계

| 구성요소 | 상태 | 검증 결과 |
|---------|------|----------|
| JWT 발급/검증 | ✅ 양호 | `JwtService`(HMAC256 서명, access+refresh 토큰) → `JwtAuthenticationFilter`(Bearer 추출, UserPrincipal 생성) → `SecurityUtils`(currentUserId/hasAnyRole) 단일 흐름 확인 |
| 프론트엔드 토큰 관리 | ✅ 양호 | `useAuth` 훅에서 `localStorage("korfarm_token")` 단일 키 사용, JWT payload 디코딩으로 roles/userId 추출 |
| API 클라이언트 | ✅ 양호 | `api.js`(토큰 선택) + `adminApi.js`(토큰 필수, 없으면 즉시 에러) 이원화 명확 |
| 역할 체계 | ✅ 양호 | 백엔드 `AuthService.resolveRoles()`에서 `HQ_ADMIN`, `ORG_ADMIN`, `STUDENT`, `PARENT` 결정. 프론트엔드 `LoginPage`에서 동일 역할명으로 라우팅 분기 |
| isAdmin 패턴 | ⚠️ 경미 | `roles.includes("HQ_ADMIN") \|\| roles.includes("ORG_ADMIN")` 패턴이 LoginPage, AdminLayout 등에서 반복. 동작에 문제 없음 |

#### 🔴 신규 발견: isPremium 로직 오류

```javascript
// useAuth.js
const isPremium = roles.includes("PAID") || roles.includes("ADMIN") || roles.includes("PREMIUM");
```

백엔드는 `HQ_ADMIN`, `ORG_ADMIN`, `STUDENT`, `PARENT`만 사용하므로, `isPremium`이 **항상 false**가 됨.
→ 유료 콘텐츠 접근 제어가 `SubscriptionService`(백엔드)에서 처리되므로 실제 기능 장애는 없으나, 프론트엔드 UI 표시에 영향 가능.

#### ⚠️ 신규 발견: refreshToken 미사용

`JwtService`에서 `createRefreshToken()` 메서드가 존재하지만, 프론트엔드에서 refreshToken을 저장/사용하지 않음. accessToken 만료 시 수동 재로그인 필요.

## 8. 종합 평가

### 강점 (코드 레벨 검증 완료)

1. **경제 시스템 = 핵심 접착제** — 7개 서비스 의존, 모든 학습 활동→씨앗 보상→인벤토리 표시 흐름 완결
2. **인증/인가 다중 방어** — useAuth(프론트) + AdminGuard(백엔드) + SecurityConfig(경로) 일관 적용
3. **학부모 API 체계** — `/v1/parents/children/...` 별도 경로, 9개 페이지에서 활용, verifyParentChildLink 인증
4. **관리자 시스템 공통화** — AdminLayout + useAdminList + adminApi 3층 아키텍처
5. **학습→과제→글쓰기 삼각 연결** — assignmentId 쿼리 파라미터로 자연스러운 컨텍스트 전달
6. **통합 성적표** — 5개 독립 데이터 소스 → 단일 서비스 → 3가지 접근 경로 → 4개 차트 컴포넌트
7. **CSS 조직** — 45개 import가 기능 그룹별로 깔끔하게 분리, 교차 사용 없음

### 약점 (코드 레벨 확인된 이슈)

1. **커뮤니티 프론트엔드 미완성** — 게시글 수정/삭제, 댓글 삭제, 신고 접수 UI 4건 없음 (백엔드 모두 준비됨)
2. **쇼핑 정적↔DB 심각한 불일치** — ID 형식 다름, 상품 수 다름(6 vs 3), API 미사용
3. **isPremium 로직 오류** — 프론트엔드가 존재하지 않는 역할명 체크
4. **refreshToken 미활용** — 생성만 하고 저장/갱신 로직 없음
5. **useLearningCatalog 죽은 코드** — 훅 존재하나 어디서도 미사용
6. **AssignmentsPage 경로 오류** — `/learn/` 사용 중, `/learning/`이 올바른 경로

핵심 학습 경험 흐름(학습→테스트→대결→보상→성적표)의 연결성이 매우 우수하다. 경제 시스템이 전체를 관통하는 접착제 역할을 잘 수행한다.

**계획 대비 신규 발견 사항 3건**:
1. `isPremium` 로직이 잘못된 역할명 체크 (기능 장애 가능)
2. `refreshToken` 생성만 하고 미사용 (토큰 만료 시 재로그인 필요)
3. `AssignmentsPage` 라우터 경로 오류 (`/learn/` → `/learning/`)

**우선 수정 권장 순서**:
1. AssignmentsPage 경로 오류 수정 (즉시 — 사용자 영향)
2. isPremium 로직 수정 (단기 — 역할명 일치)
3. 커뮤니티 수정/삭제/신고 UI 추가 (중기 — 백엔드 준비됨)
4. 쇼핑 정적→API 전환 (중기 — ID 정규화 필요)
5. refreshToken 활용 (장기 — UX 개선)
