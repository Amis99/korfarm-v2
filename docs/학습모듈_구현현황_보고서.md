## 1. 엔진 공통 시스템

### 1-1. EngineShell (학습 엔진 셸)

학습 엔진의 최상위 래퍼. 모든 학습 모듈은 이 셸 안에서 동작하며, 시간·씨앗·진행도·결과를 통합 관리한다.

**파일**: `frontend/src/engine/core/EngineShell.jsx`

#### 상태 흐름

```
READY → (start) → RUNNING → (finish) → FINISHED
                     ↕ (pause/resume)
                   PAUSED
```

- `READY`: 학습 대기. 모듈이 `start()`를 호출하면 타이머 시작.
- `RUNNING`: 학습 진행 중. 1초마다 `timeLeft` 감소.
- `PAUSED`: 일시정지. 씨앗 소진 + `preventAutoFinish` 모드에서만 사용.
- `FINISHED`: 학습 종료. 결과 요약 화면(ResultSummary) 표시.

#### 시간 관리

| 항목 | 설명 |
|------|------|
| 기본 시간 | `content.timeLimitSec` 값 사용, 없으면 **180초(3분)** |
| 최대 시간 | `timeLimit` 이상으로는 증가하지 않음 (`Math.min(timeLimit, ...)`) |
| 최소 시간 | 0 이하로는 감소하지 않음 (`Math.max(0, ...)`) |
| 감소 주기 | `RUNNING` 상태에서 1초(1000ms)마다 1씩 감소 |
| 시간 조정 | `adjustTime(delta)` — 정답 시 양수, 오답 시 음수로 시간 증감 |
| 시간 펄스 | 시간 증가 시 "gain", 감소 시 "loss" 클래스 적용 (520ms 지속) |
| 시간 소진 시 | 씨앗 1개 감소 → 시간 `timeLimit`으로 리셋 → 다시 시작 |

#### 시간바 (TimeBar)

| 항목 | 설명 |
|------|------|
| 표시 방식 | 가로 진행 바 (너비 = `timeLeft / timeLimit × 100%`) |
| 숫자 표시 | **없음** — 바의 길이로만 시간을 표현 |
| 색상 | 초록→주황 그라디언트 (`#6da475` → `#ff8f2b`) |
| 정답 애니메이션 | 밝기 증가 + Y축 스케일 팝 (480ms) |
| 오답 애니메이션 | 어두워짐 + X축 흔들림 (420ms) |
| 접근성 | `role="progressbar"`, `aria-valuemin/max` 속성 포함 |

#### 씨앗 시스템

**씨앗 초기값**

| 조건 | 값 |
|------|------|
| 기본값 | `content.seedReward.count` (백엔드 결정) |
| 폴백 | 3개 |

**씨앗 소진 메커니즘**

1. 시간이 0에 도달하면 씨앗 1개 감소
2. 씨앗이 아직 남아있으면 → 시간을 `timeLimit`으로 리셋, 학습 계속
3. 씨앗이 0이 되면:
   - `preventAutoFinish` 모드: 일시정지 상태로 전환 (`seedExhausted = true`)
   - 일반 모드: 즉시 `finish(false)` 호출 → 학습 실패 종료

**씨앗 보상 규칙**

| 조건 | 보상 |
|------|------|
| 정확도 < 70% | 씨앗 0개 (실패) |
| 정확도 ≥ 70% | 현재 남은 씨앗 수만큼 획득 |
| 정확도 = 100% (만점) | 획득 씨앗 **2배** |
| 모듈이 `choice_judgement` | 획득 씨앗 **3배** (만점이면 6배) |

**씨앗 종류 및 농장 매핑**

| 씨앗 종류 | 이름 | 가중치 | 대응 농장 |
|-----------|------|--------|----------|
| `seed_wheat` | 밀 | 70 | 어휘(vocab), 문법(grammar) |
| `seed_rice` | 쌀 | 70 | 독해(reading), 내용숙지(content) |
| `seed_corn` | 옥수수 | 70 | 배경지식(background), 국어개념(concept) |
| `seed_grape` | 포도 | 30 | 논리사고력(logic), 선택지판별(choice) |
| `seed_apple` | 사과 | 30 | 서술형(writing) |

- 농장 학습이면: `contentType` → 농장ID → 고정 씨앗 종류
- 농장 매핑이 없으면: 가중치 기반 랜덤 선택 (밀·쌀·옥수수 가중 높음)

**contentType → 농장 매핑 전체 목록**

| contentType | 농장ID |
|-------------|--------|
| VOCAB_BASIC, VOCAB_DICTIONARY | vocab |
| GRAMMAR_WORD_FORMATION, GRAMMAR_SENTENCE_STRUCTURE, GRAMMAR_PHONEME_CHANGE, GRAMMAR_POS | grammar |
| READING_NONFICTION, READING_LITERATURE | reading |
| CONTENT_PDF, CONTENT_PDF_QUIZ | content |
| BACKGROUND_KNOWLEDGE, BACKGROUND_KNOWLEDGE_QUIZ | background |
| LANGUAGE_CONCEPT, LANGUAGE_CONCEPT_QUIZ | concept |
| LOGIC_REASONING, LOGIC_REASONING_QUIZ | logic |
| CHOICE_JUDGEMENT | choice |
| WRITING_DESCRIPTIVE | writing |
| PRO_READING, PRO_ANSWER | reading |
| PRO_VOCAB | vocab |
| PRO_BACKGROUND | background |
| PRO_LOGIC | logic |

#### 정확도 판정

| 항목 | 규칙 |
|------|------|
| 정확도 계산 | `(정답 수 / 전체 답변 수) × 100` (소수점 반올림) |
| 성공 조건 | 모듈이 `finish(true)` 호출 **AND** 정확도 ≥ 70% |
| 실패 조건 | 모듈이 `finish(false)` 호출 **OR** 정확도 < 70% |

#### 진행도 추적

모듈별로 전체 단계 수를 자동 계산한다.

| 모듈 | 전체 단계 수 계산 방식 |
|------|---------------------|
| worksheet_quiz | 문제별 답변 단위 합산 (빈칸형은 빈칸 수, 문장조립형은 파트 수, 기타 1) |
| reading_intensive | 타임라인 수 |
| reading_training | 정독 타임라인 수 + 복기(있으면 1) + 확인 질문 수 + INTENSIVE 오답 수 |
| recall_cards | 카드 수 |
| confirm_click | 단계 수 |
| choice_judgement | 질문 수 |
| phoneme_change | 아이템 수 |
| word_formation | 아이템 수 |
| sentence_structure | 문장 수 |
| content_pdf | 모든 페이지의 문제 단위 합산 |

현재 진행도 = 고유 답변 ID 수 (중복 제거). `reading_training`만 추가로 INTENSIVE 오답 수를 합산.

#### 결과 기록

**localStorage 저장**: `korfarm_learning_logs` 키에 학습 로그 배열 누적
- 콘텐츠ID, 타입, 제목, 모듈키, 시작/종료 시간, 모든 답변 기록, 요약 포함

**서버 API 호출** (`farmLogId`가 있을 때):
- `POST /v1/learning/farm/complete`
- 전송 데이터: `log_id`, `score`(정확도), `earned_seed`(획득 씨앗), `seed_type`(씨앗 종류), `accuracy`

#### 결과 요약 화면 (ResultSummary)

학습 종료 후 표시되는 결과 카드.

| 표시 항목 | 내용 |
|-----------|------|
| 진행도 | `풀은 수 / 전체 수` + 진행 바 |
| 정답 수 | 숫자 + 바 (초록) |
| 오답 수 | 숫자 + 바 (빨강) |
| 정확도 | 백분율(%) + 바 (100%=완벽, ≥70%=통과, <70%=실패) |
| 소요 시간 | `분:초` 형식 + 시계 아이콘 (크기가 소요 시간에 비례) |
| 획득 씨앗 | 씨앗 종류 이름 + 개수 + 씨앗 아이콘 (최대 12개 표시) |

**결과 카드 스타일**:
- 만점 + 씨앗 획득 → "perfect" (완벽 배경)
- 씨앗 획득 → "earned" (성공 배경)
- 씨앗 없음 → "empty" (실패 배경)

**씨앗 아이콘 색상**:
- 밀: `#e8b84b`
- 쌀: `#d4d4c0`
- 옥수수: `#f5c542`
- 포도: `#9b6bb0`
- 사과: `#e85050`

#### 헤더 UI 구성

| 위치 | 내용 |
|------|------|
| 좌상단 | 국어농장 로고 (홈 링크) |
| 중앙 상단 | 콘텐츠 제목 |
| 우상단 | 학습 타입 · 레벨 (예: "어휘 학습 · 소쉬르1") |
| 우상단 2 | 영역 · 세부영역 (예: "어휘 · 기본") |
| 좌하단 | 씨앗 아이콘 (현재 개수만큼 표시) |
| 우하단 | 시간바 |

#### 푸터 UI 구성

| 위치 | 내용 |
|------|------|
| 좌측 | "학습 종료" 버튼 |

#### 인쇄 기능

- 브라우저 인쇄 다이얼로그 호출 (`window.print()`)

- content_pdf: 페이지별로 "N페이지 문제" 그룹 분리
- 빈칸형: `____` → `(          )` 치환

### 1-2. EngineContext (엔진 컨텍스트)

**파일**: `frontend/src/engine/core/EngineContext.jsx`

모듈이 엔진 기능에 접근하기 위한 React Context.
모듈 내부에서 `useEngine()` 훅으로 다음 기능을 사용한다.

| 제공 값 | 타입 | 설명 |
|---------|------|------|
| `status` | `"READY" \| "RUNNING" \| "PAUSED" \| "FINISHED"` | 현재 학습 상태 |
| `timeLeft` | 숫자(초) | 남은 시간 |
| `timeLimit` | 숫자(초) | 전체 제한 시간 |
| `seed` | 숫자 | 현재 남은 씨앗 수 |
| `setSeed` | 함수 | 씨앗 수 직접 변경 |
| `adjustTime` | 함수 | 시간 증감 (`adjustTime(+20)` 또는 `adjustTime(-40)`) |
| `recordAnswer` | 함수 | 답변 기록 (`{id, correct, ...}`) |
| `start` | 함수 | 학습 시작 |
| `pause` | 함수 | 일시정지 |
| `resume` | 함수 | 재개 |
| `finish` | 함수 | 학습 종료 (`finish(성공여부, 옵션)`) |
| `seedExhausted` | 불리언 | 씨앗 소진 상태 |
| `resetRound` | 함수 | 라운드 리셋 |
| `setPageProgress` | 함수 | 페이지 진행도 설정 (ContentPdf용) |

### 3-1. WorksheetQuizModule (워크시트 퀴즈)

**파일**: `frontend/src/engine/modules/WorksheetQuizModule.jsx`
**module_key**: `worksheet_quiz`
**대응 contentType**: VOCAB_BASIC, VOCAB_DICTIONARY, BACKGROUND_KNOWLEDGE, LANGUAGE_CONCEPT, LOGIC_REASONING, WRITING_DESCRIPTIVE, GRAMMAR_POS 등

#### 화면 구성

- **시험지 레이아웃**: 2단 컬럼으로 문제 목록 표시 (좌·우 분리)
- **페이지 분할**: 문제 높이를 측정하여 한 페이지에 안 들어가면 다음 페이지로 자동 분할
- **현재 문제 하이라이트**: 활성 문제에 `active` 클래스 적용
- **채점 표시**: 완료된 문제 옆에 ○(정답) 또는 ／(오답) 표시
- **하단 컨트롤**: PDF 보기 버튼(있을 때), 진행 카운터 (현재/전체)
- **사전 카드**: 어휘 학습 시 표제어·품사·뜻·용례를 카드 형태로 표시

#### 지원 문제 유형

| 유형 | 설명 |
|------|------|
| 일반 선택 | `stem`(문제문) + `choices`(선택지) → 모달에서 선택 |
| 빈칸 채우기 (FILL_BLANKS) | `template`에 `____` 위치, 빈칸별 `choices` → 순차 선택 |
| 문장 조립 (SENTENCE_BUILDING) | `sentenceParts` → FILL_BLANKS로 자동 정규화 후 순차 선택 |
| 사전 뜻→낱말 (DICT_MEANING_TO_WORD) | 사전 카드 표시, 표제어 빈칸 → 선택지에서 맞히기 |
| 낱말→사전 빈칸 (WORD_TO_DICT_FILL) | 사전 카드 + 정의 빈칸 → template 기반 채우기 |
| 다의어/동음이의어 (HOMONYM_EXAMPLE) | 예문에서 표제어 빈칸 → 뜻 매칭 |
| 원고지 모드 (MANUSCRIPT) | `render: "MANUSCRIPT"` 또는 `contentType: WRITING_DESCRIPTIVE` → 원고지 그리드 UI |

#### 하이라이트 기능

- **범위 기반**: `highlight.range` (시작/끝 인덱스)로 문제문 일부를 강조
- **텍스트 기반**: `highlight.text`로 일치하는 모든 텍스트를 강조
- 하이라이트된 부분이 QuestionModal의 앵커 위치가 됨

#### 타이머 규칙

| contentType | 정답 시간 | 오답 시간 | 비고 |
|-------------|----------|----------|------|
| BACKGROUND_KNOWLEDGE | +30초 | -30초 | |
| BACKGROUND_KNOWLEDGE_QUIZ | +30초 | -30초 | |
| GRAMMAR_POS | +20초 | -40초 | |
| 그 외 (어휘, 국어개념 등) | +0초 | -0초 | JSON에 scoring이 있으면 그 값 사용 |

- JSON의 `question.scoring` 필드가 있으면 해당 값이 우선 적용됨
- JSON에 없을 때 위 기본값이 적용됨

#### 오답 처리

| contentType | 오답 시 행동 | 설명 |
|-------------|------------|------|
| GRAMMAR_POS | **재도전** (정답까지) | `requireCorrect` 기본값 true |
| 그 외 | 틀림 표시 후 다음 문제로 진행 | `requireCorrect` 기본값 false |

- 개별 문제의 JSON에 `requireCorrect: true`가 있으면 해당 문제만 재도전 강제
- 빈칸 채우기: 빈칸별로 순차 진행, 모든 빈칸 완료 시 다음 문제

#### 시작 방식

| 조건 | 행동 |
|------|------|
| `payload.requireStart = true` | PDF 미리보기 + "학습 시작" 버튼 표시 → 클릭 시 시작 |
| `payload.requireStart = false` | 자동 시작 |

#### PDF 보기 기능

- 풀이 중 "PDF 보기" 버튼 클릭 → 오버레이 팝업으로 PDF 표시
- "보기 종료" 버튼으로 닫음
- PDF 보는 중에도 엔진 시간은 계속 진행

#### 피드백

- 정답/오답 시 QuestionModal에 마크 표시 (420ms)
- 정답 후 420ms 대기 → 자동으로 다음 문제 진행
- 마지막 문제 완료 시 `finish(true)` 호출

### 3-2. ReadingTrainingModule (독해 연습 3단계)

**파일**: `frontend/src/engine/modules/ReadingTrainingModule.jsx`
**module_key**: `reading_training`
**대응 contentType**: READING_NONFICTION, READING_LITERATURE

#### 3단계 구조

```
INTENSIVE (정독) → RECALL (복기) → CONFIRM (확인)
```

- 각 단계는 데이터가 있을 때만 활성화 (없으면 건너뜀)
- 모든 단계 완료 또는 가용 단계 없으면 `finish(true)`

---

#### 스테이지 1: INTENSIVE (정독 훈련)

**화면 구성**:
- 지문 텍스트 전체 표시
- 현재 질문에 해당하는 부분을 하이라이트
- 하단에 진행 카운터 (현재/전체)
- 하이라이트 위치에 맞춰 QuestionModal 표시

**하이라이트 방식**:
- `ranges` 배열: 다중 범위 하이라이트 (paragraphId + start/end)
- `paragraphIds` 배열: 문단 전체 하이라이트
- `paragraphId` + `range`: 단일 범위 하이라이트
- `paragraphId` + `mode: "PARAGRAPH"`: 문단 전체 하이라이트

**타이머 규칙**:
- 정답: **+20초**
- 오답: **-40초**
- JSON의 `question.scoring`이 있으면 해당 값으로 덮어씀

**오답 처리**:
- 기본적으로 오답 선택지 제거 (`eliminateWrongChoice: true`)
- 정답을 맞힐 때까지 다음 단계로 진행 불가
- 오답 시 해당 선택지만 사라지고 나머지로 다시 풀기

**피드백**:
- QuestionModal에 정답/오답 마크 표시 (1000ms)
- 정답 후 1000ms 대기 → 다음 단계 진행

**완료 조건**: 모든 타임라인 단계 완료 → RECALL로 전환

---

#### 스테이지 2: RECALL (복기 학습)

**화면 구성**:
- 상단: 빈 슬롯 배열 (정답 순서대로 카드를 배치할 공간)
- 하단: 셔플된 카드 풀 (정답 순서와 다르게 섞여 있음)
- 하단 푸터: 씨앗 수 표시 + "제출" 버튼
- 정답/오답 시 각 슬롯에 정답/오답 아이콘 표시

**조작 방법**:
- **드래그앤드롭**: 카드를 풀에서 슬롯으로, 슬롯 간 이동, 슬롯에서 풀로 반환
- **터치 지원**: 포인터 이벤트로 터치 디바이스에서도 드래그 가능
- **슬롯 간 교환**: 이미 배치된 슬롯에 새 카드를 드롭하면 기존 카드와 교환
- FLIP 애니메이션: 카드 이동 시 Web Animations API로 부드러운 전환

**채점**:
- "제출" 클릭 → 전체 순서를 정답 순서와 비교
- 모든 슬롯이 올바르면 → 정답
- 하나라도 틀리면 → 오답

**정답 시**: 성공 피드백 → 600ms 후 CONFIRM으로 전환
**오답 시**:
- 각 슬롯별로 정답/오답 아이콘 표시
- 씨앗 감소 (기본 페널티 1, `recall.seedPenalty` 또는 `seedPool.wrongPenaltySeed`로 설정 가능)
- 씨앗이 0이 되면 `finish(false)` → 학습 실패

**완료 조건**: 정답 제출 → CONFIRM으로 전환

---

#### 스테이지 3: CONFIRM (확인 학습)

**화면 구성**:
- 지문 텍스트를 글자 단위로 렌더링 (각 글자가 클릭 가능)
- 상단에 질문 프롬프트 + 진행 카운터
- 정답 범위에 해당하는 글자를 클릭하면 정답
- 오답 시 정답 범위 자동 하이라이트

**위치 매칭 방식**:
- `answerRanges` 배열로 정답 범위 지정 (paragraphId + start/end)
- `answerRanges`가 없으면 `answerText`로 지문에서 자동 검색
- 같은 글자여도 **위치가 다르면 오답** (인덱스 기반)

**일치 모드**:
- `ANY` (기본): 정답 범위 중 하나만 클릭하면 정답
- `ALL`: 모든 정답 범위를 찾아야 다음 진행 (진행 카운터: "찾은 표현: N/M")

**타이머 규칙**:
- 정답: **+30초**
- 오답: **-45초**
- JSON의 `question.scoring`이 있으면 해당 값으로 덮어씀

**오답 처리**:
- `revealOnWrong` (기본 true): 오답 시 정답 범위를 하이라이트로 표시
- 900ms 후 자동으로 다음 질문 진행
- 오답 후 재도전 없음 (자동 진행)

**완료 조건**: 모든 확인 질문 완료 → `finish(true)`

---

### 3-4. RecallCardsModule (복기 카드 단독)

**파일**: `frontend/src/engine/modules/RecallCardsModule.jsx`
**module_key**: `recall_cards`

ReadingTrainingModule의 RECALL 스테이지를 독립 모듈로 제공하되, 더 단순한 구현.

#### 화면 구성

- "지문 요약 카드 정렬" 안내 텍스트
- 카드 목록 (번호 + 텍스트 + 위로/아래로 버튼)
- 정답 순서 표시 영역 (오답 후)
- 하단: 남은 씨앗 표시 + "제출하기" 버튼
- 피드백 ("정답입니다!" / "오답입니다!")

#### 조작 방법

- **드래그앤드롭**: 카드를 다른 카드 위에 드롭하면 위치 교환
- **위로/아래로 버튼**: 인접 카드와 위치 교환

#### 타이머 규칙

- 오답 시 **-20초** 고정
- 정답 시 시간 변화 없음

#### 씨앗 관리

- 자체 `seed` 상태 관리 (초기값: `payload.seedPool.initial` 또는 3)
- 오답 시 `payload.seedPool.wrongPenaltySeed`만큼 감소 (기본 1)
- 씨앗 0이 되면 `finish(false)`

**참고**: ReadingTrainingModule의 RECALL은 EngineShell의 `seed`/`setSeed`를 사용하지만, RecallCardsModule은 자체 `seed` 상태를 사용한다는 차이가 있다.

#### 오답 처리

- 오답 시 정답 순서를 텍스트 목록으로 표시
- 씨앗이 남아있으면 재도전 가능

#### 시작 방식

- 자동 시작

#### 완료

- 정답 제출 시 `finish(true)` → 즉시 종료 (대기 없음)

#### ReadingTrainingModule의 RECALL과의 차이점

| 항목 | ReadingTrainingModule RECALL | RecallCardsModule |
|------|----------------------------|-------------------|
| 카드 배치 | 상단 슬롯 + 하단 풀 분리 | 단일 목록 내 재정렬 |
| 드래그 | 풀→슬롯, 슬롯↔슬롯 | 카드↔카드 |
| 위로/아래로 버튼 | 없음 (드래그만) | 있음 |
| 이동 애니메이션 | Web Animations API | 없음 |
| 터치 지원 | 포인터 이벤트 | 기본 드래그만 |
| 씨앗 관리 | EngineShell의 seed 사용 | 자체 seed 상태 |
| 오답 표시 | 슬롯별 정답/오답 아이콘 | 정답 순서 텍스트 목록 |
| 시간 차감 | 없음 (씨앗 차감만) | -20초 |

### 3-5. ConfirmClickModule (확인 학습 단독)

**파일**: `frontend/src/engine/modules/ConfirmClickModule.jsx`
**module_key**: `confirm_click`

ReadingTrainingModule의 CONFIRM 스테이지를 독립 모듈로 제공하되, TokenPassage 기반.

- 상단: 질문 프롬프트 + 진행 카운터 (현재/전체)
- 중앙: TokenPassage 컴포넌트 (토큰 단위 지문)
- 피드백 ("정답입니다!" / "오답입니다!")
- 오답 후: "다음 문제" 버튼

#### 위치 매칭 방식

- ReadingTrainingModule은 **글자 단위** 인덱스 매칭
- ConfirmClickModule은 **토큰 ID** 매칭 (`answerTokenRefs` 배열)
- 정답 토큰을 클릭하면 정답, 그 외 토큰 클릭 시 오답

#### 타이머 규칙

- 정답: **+30초**
- 오답: **-45초**
- JSON의 `question.scoring`이 있으면 해당 값으로 덮어씀

#### 오답 처리

- `revealOnWrong = true` (기본): 오답 시 정답 토큰 하이라이트
- 오답 후 "다음 문제" 버튼 표시 → 수동 클릭으로 진행
- (ReadingTrainingModule은 900ms 후 자동 진행이므로 방식 차이)

#### 시작 방식

- 자동 시작

#### 완료

- 마지막 질문의 정답 클릭 시 `finish(true)`
- 마지막 질문의 오답 후 "다음 문제" 클릭 시 `finish(false)`

#### ReadingTrainingModule의 CONFIRM과의 차이점

| 항목 | ReadingTrainingModule CONFIRM | ConfirmClickModule |
|------|------------------------------|-------------------|
| 지문 렌더링 | 글자 단위 (모든 글자 클릭 가능) | 토큰 단위 (TokenPassage) |
| 정답 매칭 | 인덱스 범위 기반 (`answerRanges`) | 토큰 ID 기반 (`answerTokenRefs`) |
| ALL 모드 | 지원 (다중 범위 모두 찾기) | 미지원 |
| 오답 후 진행 | 900ms 자동 진행 | "다음 문제" 수동 버튼 |

### 3-6. ChoiceJudgementModule (선택지 판별)

**파일**: `frontend/src/engine/modules/ChoiceJudgementModule.jsx`
**module_key**: `choice_judgement`
**대응 contentType**: CHOICE_JUDGEMENT

#### 화면 구성

- 좌측: 문제 문항(`stem`) + 선택지 목록 (버튼 형태)
- 우측: TokenPassage(토큰 기반 지문) + 명제 목록
- 상단: 현재 명제 정보 또는 안내 텍스트
- 피드백 ("정답입니다!" / "오답입니다!")

#### 풀이 흐름

1. **선택지 클릭**: 한 선택지를 클릭하면 해당 선택지의 명제(propositions) 목록이 표시됨
2. **명제별 근거 찾기**: 각 명제에 대해 지문에서 증거 토큰(evidenceTokens)을 클릭
   - 올바른 증거 클릭 → 정답 (+20초)
   - 잘못된 토큰 클릭 → 오답 (-40초) + 재도전 (다음 명제로 안 넘어감)
3. **명제 완료**: 증거를 맞히면 해당 명제에 O/X 마크 표시
4. **모든 명제 완료**: 선택지의 최종 판정 표시
   - 정답 선택지(finalIsCorrectChoice = true) → "정답" 마크 + 다음 아이템
   - 오답 선택지 → 부정문이면 "O", 긍정문이면 "X" 마크 + 다른 선택지 계속
5. **아이템 완료**: 모든 아이템 완료 시 `finish(true)`

**부정문 감지**: 문항(`stem`)에 "적절하지"가 포함되면 부정형으로 판단 → 오답 선택지에 "O" 표시

#### 타이머 규칙

- 정답: **+20초**
- 오답: **-40초**
- 고정값 (JSON 오버라이드 없음)

#### 오답 처리

- 증거 토큰이 틀리면 해당 명제에서 재도전 (다음 명제로 넘어가지 않음)
- 선택지 자체가 정답이 아니면 해당 선택지에 마크 표시 후 다른 선택지 선택 가능

#### 씨앗 보상

- EngineShell에서 `choice_judgement` 모듈에 대해 **씨앗 3배** 자동 적용

#### 시작 방식

- 자동 시작

### 3-7. PhonemeChangeModule (음운 변동 분석)

**파일**: `frontend/src/engine/modules/PhonemeChangeModule.jsx`
**module_key**: `phoneme_change`
**대응 contentType**: GRAMMAR_PHONEME_CHANGE

#### 화면 구성

- 상단: 단어 표면형(`surface`) + 진행 카운터 (단어/전체 · 단계/전체)
- 중앙: 셀 그리드 — 각 셀에 음운 텍스트 표시
  - **환경 셀** (`envCellNos`): 초록색 하이라이트
  - **대상 셀** (`targetCellNo`): 파란색 하이라이트
- 피드백 ("정답입니다!" / "오답입니다!")
- QuestionModal로 선택형 질문

#### 데이터 구조

- `words[]`: 각 단어별 셀 배열과 단계 배열
- `words[].cells[]`: 셀 번호 + 텍스트 (음운 표시)
- `words[].steps[]`: 단계별 질문 (stepId, choices, answerId, 환경/대상 셀, 정답/오답 동작)

#### 질문 유형

| `questionType` | 모달 프롬프트 |
|---------------|------------|
| `RULE_EXPLANATION` | "규칙을 고르세요." |
| 그 외 | "변동 결과를 고르세요." |

#### 타이머 규칙

- 정답: `step.onCorrect.deltaSec` (기본 0)
- 오답: `step.onWrong.deltaSec` (기본 0)
- **모든 값이 JSON 데이터에 의존** (모듈 자체 기본값 없음)

#### 오답 처리

- `step.onWrong.retry = true`: 오답 시 같은 단계에서 재도전
- `step.onWrong.retry = false/undefined`: 다음 단계로 진행

#### 정답 시 셀 업데이트

- `step.onCorrect.applyCellText`: 정답 시 특정 셀의 텍스트를 변경
- 예: 음운 변동 결과를 셀에 반영 (`{cellNo: 3, newText: "ㄴ"}`)

#### 진행 흐름

1. 단어 → 단계 순차 진행
2. 정답 시 셀 텍스트 업데이트 + 420ms 대기 → 다음 단계
3. 모든 단어의 모든 단계 완료 → `finish(true)`

#### 시작 방식

- 자동 시작

### 3-8. WordFormationModule (단어의 형성 분석)

**파일**: `frontend/src/engine/modules/WordFormationModule.jsx`
**module_key**: `word_formation`
**대응 contentType**: GRAMMAR_WORD_FORMATION

#### 화면 구성

- 상단: 단어 표시 (`item.word`)
- 중앙: 형태소 스트립 — 각 형태소를 칩(chip) 형태로 표시
  - 현재 단계의 대상 형태소에 `active` 클래스
- 피드백 ("정답입니다!" / "오답입니다!")
- QuestionModal로 선택형 질문

#### 풀이 흐름

**아이템별 단계 진행**:

1. **형태소 개수 세기** (COUNT): 모달에서 숫자 선택
2. **형태소별 분석**: 각 형태소의 이름/종류 선택 (11종: 어근, 접두사, 접미사 등)
3. **결합 질문** (mergeQuestions): 형태소 3개 이상일 때 결합 방향(좌/우) 선택
   - 결합 → 합성어/파생어 분류
   - 최종 단어 종류 판별 (단일어/합성어/파생어)
4. 모든 아이템 완료 → `finish(true)`

#### 질문 모달 구성

| 단계 | 모달 제목 | 모달 프롬프트 | 선택지 |
|------|---------|------------|--------|
| COUNT | "형태소 개수" | "형태소 개수를 고르세요." | 숫자 목록 |
| 분석 | "형태소 분석" | "정답을 고르세요." | step.choices |
| 결합 | "결합 질문" | mergeQuestion.ask | "왼쪽" / "오른쪽" |

#### 타이머 규칙

- 일반 단계: 정답 **+20초**, 오답 **-40초**
  - JSON의 `step.delta.correct`/`step.delta.wrong`이 있으면 해당 값 사용
- 결합 질문: 정답 **+20초**, 오답 **-40초** (고정)

#### 오답 처리

- 일반 단계: **재도전** (정답할 때까지 다음으로 안 넘어감)
- 결합 질문: 오답이어도 420ms 후 다음 질문으로 진행

#### 시작 방식

- 자동 시작

### 3-9. SentenceStructureModule (문장의 짜임 분석)

**파일**: `frontend/src/engine/modules/SentenceStructureModule.jsx`
**module_key**: `sentence_structure`
**대응 contentType**: GRAMMAR_SENTENCE_STRUCTURE

#### 화면 구성

- 상단 지시문: "서술어 **{서술어 텍스트}**에 호응하는 성분을 모두 선택하세요." + 진행 카운터
  - 서술어가 없으면: "문장 성분을 선택하세요."
- 중앙: 토큰 칩 배열 — 각 토큰을 버튼으로 표시
  - 역할별 색상 구분 (role-1, role-2, role-3 CSS 클래스)
  - 선택된 토큰에 `active` 클래스
  - 오답 시 정답 토큰에 `worksheet-highlight` 클래스
- 하단: "제출" 버튼
- 피드백 ("정답입니다!" / "오답입니다!")

#### 풀이 흐름

1. 문장별 `roleQueryOrder` 배열로 질문 순차 진행
2. 각 질문: 서술어 지정 → 호응 성분(targetRoles에 해당하는 토큰) 모두 선택 → 제출
3. 정답 판정: 선택한 토큰 ID 정렬 = 정답 토큰 ID 정렬이면 정답
4. 다음 질문 또는 다음 문장으로 진행
5. 모든 문장 완료 → `finish(true)`

#### 타이머 규칙

- 정답: **+20초**
- 오답: **-40초**
- 고정값 (JSON 오버라이드 없음)

#### 오답 처리

- 오답 시 정답 토큰을 하이라이트로 표시 (`showCorrect = true`)
- 선택 초기화 후 같은 질문에서 다시 시도 가능
- (단, `showCorrect`가 true인 상태에서 다시 시도 → 정답 위치를 보고 풀 수 있음)

#### 시작 방식

- 자동 시작

- PDF가 없으면: 자동 시작

## 6. 씨앗 보상 규칙 종합표

| 조건 | 적용 순서 | 보상 |
|------|---------|------|
| 정확도 < 70% | - | 씨앗 0개 (실패) |
| 정확도 ≥ 70% | 1단계 | 남은 씨앗 수만큼 획득 |
| 정확도 = 100% (만점) | 2단계 | 1단계 결과 × **2배** |
| 모듈 = choice_judgement | 3단계 | 2단계 결과 × **3배** |

**예시 계산**:
- 씨앗 3개, 정확도 85% → 3개 획득
- 씨앗 3개, 정확도 100% → 3 × 2 = **6개** 획득
- 씨앗 3개, 정확도 100%, 선택지 판별 → 3 × 2 × 3 = **18개** 획득
- 씨앗 3개, 정확도 80%, 선택지 판별 → 3 × 3 = **9개** 획득
- 씨앗 2개 (시간 소진 1회), 정확도 90% → 2개 획득
- 씨앗 0개 (시간 소진 3회) → 자동 실패 종료 (씨앗 0개)
